# 制作手法とサンプルのsubagent評価

記録日: 2026-10-03。二つのsubagentに、プレイヤー表示を順に読む評価と、検証記録の再計算を分担させた。ロアは調査動機と人物の負担への関心につながった。一方、条件が成立することと、プレイヤーが条件を理解して選べることの間に不足が見つかった。

対象はコミット `498f701` のMVPと、その後に作成した[制作手法の振り返り](methods-retrospective.md)。評価前の振り返り文書のSHA-256は `458f46e4fb4af7cfaabda4ef2a5dcaea0e9f210d0ad029ad802f81dbbd8e1b0d`。評価を受け、表題と検証範囲を追記した。

## 評価の条件

| 担当 | 得た根拠 | 判断しない範囲 |
| --- | --- | --- |
| `evaluate_player` | 作者用正史・草稿・回顧を事前に読まず、CLIの本文・選択肢・残り時間を見て一手ずつ進めた。終了後に実装条件を照合 | 人間の反応、別経路の魅力、画像、ブラウザの実操作 |
| `evaluate_evidence` | 8手法の記述と一次記録を照合。Jevの生レスポンスを再集計し、保存入力から状態探索を再実行 | 物語を読む体験、画像の審美評価、制作速度の比較 |
| 統合担当 | プレイ経路を再現し、条件と本文を確認。画像11枚を補足的に目視 | 独立した画像評価、人間の初見評価、参照画像の因果的な改善効果 |

二担当へ過去の会話と互いの評価を渡さず、担当ごとに異なる入力を渡した。ただし同じ実行環境のAIによる評価であり、人間のプレイテストでも真の盲検でもない。CLIには内部変数も出る。プレイ担当は未来の効果の推測に使わないように進めたが、完全な情報遮断ではない。

API判定や画像生成は追加実行せず、既存の成果物を評価した。コードとゲームデータは変更していない。

## 物語と選択で成立していたこと

プレイ担当は、南の三調査、道修理、両側保護を選び、港経由で北へ進んだ。北の三調査後は修理できず、見送りを選んで港へ戻り、灰潮を迎えた。[段階別の判断・引用・再現コマンド](evaluations/2026-10-03-player.md)を保存した。

最初の関心はスイの「母が私の名を呼んだ晩」を差し出す申し出だった。帳面と流路の試験によって、大切な記憶を増やす前に、届く粉と流路を調べる判断へ変わった。設定の秘密が、調査する理由と判断の更新として働いた。

修理後の「道が消えた費用は、その背へ移る」という本文から、両側保護を完全な救済とは受け取らなかった。アサの運搬と翌朝のスイの仕事に代償が残り、設備の数だけでは比較できない結果になった。

北ではアドの「夜に働く返事はした。思い出を差し出す返事まで、一緒にしたつもりはない」が、夜勤を減らしたいという動機を作った。労働への同意と記憶提供への同意を分ける台詞は、人物を資源の供給役としてだけ読むことを避ける材料になった。

これは一経路を読んだAIの判断である。人物への関心や選択の魅力が人間にも生じるか、他の経路で同様に成立するかは未確認。

根拠: [南の本文](../examples/ash-estuary/tide.proposal.json)の `tide.intro.memory`、`tide.fragment.test`、`tide.fragment.repaired`、[北の本文](../examples/ash-estuary/quarry.proposal.json)の `quarry.fragment.ledger`。

## 改善の優先順位

### 高: 修理できなくなった理由が見えない

南を修理・両側保護してから北へ着くと、残り20時間。三調査後は17時間になる。北の修理は各24時間必要で、窯修理には南の未配分枠も2単位必要。この経路では六単位を使い切っている。修理行動は一覧から除かれ、現地の選択肢は見送りだけだった。

`availableActions` は実行失敗を除外し、CLIもブラウザUIもその一覧を使う。制約は意図どおりだが、選べない理由が伝わらない。プレイ担当は「夜勤を残すと決めた」というより、「表示上それしかなかった」と受け取った。統合担当もCLIで同じ表示を再現した。

改善案は、判明済みの作業を無効な選択肢として残し、必要時間・残り時間・不足資源を示すこと。南で長い修理を選ぶ前に、北にも一日作業があることを依頼や地図で知らせる。未発見の行動まで先に表示する仕様にはしない。

根拠: [候補行動の抽出](../src/player/runtime.ts)、[CLIのview](../src/cli.ts)、[ブラウザの候補表示](../src/player/ui.ts)、[北の修理条件](../examples/ash-estuary/quarry.proposal.json)の `quarry.repair-kiln` と `quarry.repair-channel`。

### 中: 基本規則より、その例外を先に学ぶ

港から南へ進む表示では、灰潮の作用、記憶を石にする不可逆な代価、粉による一潮の防護のつながりを、プレイ担当が補って読む必要があった。基本規則は作者用のブリーフにあるが、プレイヤー向けの導入は薄い。

改善案は港に短い導入を置くこと。基本規則を説明し、記憶の重要さでは効力が増えないという秘密は調査まで伏せる。説明不足の受け取り方は今回のAIによる判断で、人間とブラウザでの確認が必要。

根拠: [港の表示データ](../examples/ash-estuary/world.json)の `game.locations`、[凍結ブリーフ](../examples/ash-estuary/brief.md)。

### 中: 知識を得ると、新しい人物の事情の入口も消える

南で秘密を知って北へ行くと、ネネが息子の記憶を申し出る `quarry.intro.memory` は出ない。代わりに `quarry.intro.familiar` が「私の申し出を決めるのは、そのあとにする」と語る。この経路では申し出をまだ聞いておらず、後の撤回で事情を補う順序になった。

改善案は、プレイヤーの知識と、その人物の事情を聞いた経験を分けること。既知なら原理の説明を短くしても、ネネの申し出と息子との関係は入口に残す。単純な人物紹介なら常時表示の断片へ分ける方法もある。

根拠: [北の開示条件](../examples/ash-estuary/quarry.proposal.json)の `quarry.intro.memory`、`quarry.intro.familiar`、`quarry.fragment.nene`。同じ経路で条件と表示を照合した。

終了手段の欠落とは判断していない。プレイ担当は `finish` で三つの結末断片を確認した。`--steps` のviewには終了の案内がないが、CLI help、interactiveの`end`、ブラウザの終了ボタンには手段がある。

## 8手法の根拠の強さ

「支持」は表に記した範囲で結果を再確認できたという意味で、他の手法より優れているという判定ではない。「部分支持」は制作の成立を確認できても、狙った品質や効率への効果には未確認の部分があるという意味で使う。

| 手法 | 根拠担当の判定 | 確認できた範囲と限界 |
| --- | --- | --- |
| 原理を生活・仕事・選択へ展開する | 部分支持 | 二つの状況を作れた。プレイ評価も判断の更新と負担への関心を報告。別起点との優劣は未検証 |
| 真実・信念・資料・未確定を分ける | 支持 | 宣言された層を区別する型・検査・テストを確認。自由文の意味や宣言の正しさは別途照合が必要 |
| 基礎を凍結して局所単位で並列化する | 部分支持 | 二草稿と三実装担当の成果物を統合できた。逐次との時間・統合工数の比較はない |
| 行動を条件・費用・効果へ落とす | 支持 | 保存入力から1,153状態・840終端・14行動・2エピソード、未到達と診断0件を再現。選択の予見可能性は別の課題 |
| Jevへ判定軸を分けてまとめて聞く | 部分支持 | 生レスポンスから5条件の集計を再計算して一致。単発の時間差を確認。実提案の検出精度は未検証 |
| 採用画風を画像で参照する | 部分支持 | シーンと人物の参照履歴・画像ハッシュを確認。参照なし対照はない |
| 外見参照と演技画を分ける | 部分支持 | 5人×3種類の15枚と用途別指定を確認。実画面での使いやすさは未検証 |
| 画像を状態に対応させ局所修正を検査する | 部分支持 | 条件・修正履歴・採用版を確認。画像表示のゲームへの接続は未実装 |

Jevの世界バッチは全体31/32一致でも、情報不足の参照4件中、検出は3件だった。個別判定では2件。合成ケース24件が許容、矛盾4件、情報不足4件という構成なので、総一致率だけで問題の検出能力を判断しない。長い実提案二件は `needs-review` のままで、疑義の箇所・理由・独立した参照ラベルがない。

バッチ4呼出し796.65ms、個別32呼出し6,068.60msは保存記録と一致したが、固定順での単発結果である。安定した速度差とは扱わない。BFSもログと行動順をまとめた状態の検査で、すべての文章体験を別々に評価した数ではない。

根拠: [Jevの初期実験](jev-experiment.md)、[保存レスポンス](../results/initial/raw.json)、[MVP検証と原本へのリンク](mvp-verification.md)、[状態キーと探索](../src/player/runtime.ts)。根拠担当は初期実験とMVPのソースハッシュ、MVP入力ハッシュも照合した。全CIはこの評価では再実行していない。

## 画像の補足確認

統合担当が11枚を目視した。評価対象はB、イラの初稿・三面図・ポーズ・表情集、スイ・アサ・ネネのポーズ、ネネの表情集、南修理後のv1・v2。subagentによる独立した審美評価には含めない。

イラの髪、青い上着、緑灰色の肩布は三種類で照合でき、紙の地色・細い線・淡彩も共通していた。机越しの対話、低い点検、網を繕う手元、胸元で手袋を握る姿に構図の差があり、初稿の共通全身像から用途を分けた結果は確認できた。

イラとネネの表情には眉・視線・口元の差があるが、小さな表示でも識別できるかは確認していない。南の修正版では旧溝の暗い開口が石で塞がれ、同時に左側の網を運ぶ人物が消えた。局所修正後に全体を確認する必要性も実画像で再確認した。

次の人物生成前には一人分を実際の表示寸法で確認し、三面図は制作参照、ポーズは場面、表情は切り出して使う表示として別々に評価する。現状は画集であり、ゲームへ組み込んだ使いやすさはまだ確認していない。

根拠: [人物画集](../examples/ash-estuary/art/character-gallery.html)、[シーン画集](../examples/ash-estuary/art/gallery.html)、[南修理後v1](../examples/ash-estuary/art/scenes/tide-repaired-v1.png)、[v2](../examples/ash-estuary/art/scenes/tide-repaired-v2.png)。

## 次に確かめること

まず、設定未読の人間3人程度にブラウザで一経路を進めてもらう。修理前、北の調査後、結末で「何を残し、誰の仕事が増えるか」「粉と記憶の関係」「修理できない理由」「ネネの申し出」を自分の言葉で説明してもらう。理解、予測、人物への関心を別々に記録する。人数は問題を探すための試行規模で、好みの一般化や統計的な証明には使わない。

Jevは新しい根拠付き参照ケースで、軸ごとの見逃し・誤検出・再実行での反転を調べる。同じ意味の短い入力と長い入力を比較し、調整に使ったケースと評価用ケースを分ける。

人物・事件起点や並列制作の比較では、制作時間だけでなく統合と修正に使った時間も記録する。今回支持された契約を共通に使い、最初の起点を変えても、人物の理由と予見できる選択を作れるかを確かめる。
