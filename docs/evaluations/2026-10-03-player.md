# プレイヤー表示を順に読むAIによる一経路の評価

評価日: 2026-10-03。対象: 既存の `.tmp/demo-project` を `pnpm narrative play` で再生した本文・選択肢。人間のプレイテストでも真の盲検でもない。制作手法の回顧、作者用正史、草稿、他の評価を事前に読まず、各状態を見てから次の一手を選んだ。CLIには内部変数も出力されるので、未来の行動名や効果を推測する材料には使わず、本文・選択肢・残り時間を判断材料にした。ただし完全な情報遮断ではない。

本メモの「初見記録」は実行途中に記録した判断を整理したもの。「終了後照合」は完了後に資料を読んで得た説明であり、当時知っていたこととは分けている。コード・制作資料・画像は変更していない。

## 成立していた体験（3点）

1. **独自設定が調査の理由になった。** 記憶を差し出す住民の台詞から、犠牲を足す前に流路を調べる行動へ関心が移った。「沈着の観察だけでは効力を言えない」という段階を経るので、秘密が単なる設定説明ではなく判断の更新として現れた。
2. **救済の費用が人の仕事として残った。** 南の両側保護は、アサの背と翌朝のスイの仕事に結びつく。一潮の設備保護を達成しても、運搬の継続負担がある。この経路では修理を道徳的な完全解とは受け取らなかった。
3. **人物は材料供給役に留まらなかった。** アドの労働への返事と記憶提供への返事を分ける台詞、ネネ自身の申し出撤回が、記憶を資源として数える仕組みに対して本人の選択を残した。アドの夜勤を減らしたいという動機が生じた。

## 問題（3点）

1. **高: 他地域へ及ぶ制約が、選べない理由として届かない。** 再現条件は上記経路。北到着時に残り20時間、調査後17時間となり、修理は一度も表示されない。初見では北の失敗を自分の時間配分と結びつけきれなかった。終了後照合では、窯・溝はともに24時間、さらに窯は未配分枠2以上が必要（game.json:807 / :845）。南の六単位を使い切ったので窯は資源でも不可。runtime の availableActions（src/player/runtime.ts:105）は実行失敗を catch して除外する。改善案は、判明済みの作業を無効表示し「24時間必要、残り17時間」「南の枠2単位が必要」など理由を添えること。南の修理前に北作業の規模を地図や依頼文で予告すると、地域間の犠牲を自覚して選べる。
2. **中: 基本の超常規則より先に、その例外を学ぶ。** 港→南の初見経路では、灰潮が金属・石を侵食すること、記憶が石になって失われること、焼成・粉砕した粉が一潮守ることを、最初に説明する本文を見なかった。「母の晩を差し出す」が早く出るため、感情的な代価は伝わるが因果を補って読む負担がある。終了後の brief.md:13–15 に基本規則は明記されていた。秘密の開示を守ることと、基本規則を導入することは両立する。改善案は港に短い基本説明を置き、効力が記憶の重さに依存しない秘密だけを調査まで留める。ブラウザでは promise と「記憶粉の在庫」は出る（src/player/ui.ts:75 / :79）が、それだけで因果を理解できるかは未確認。
3. **中: 先に知識を得ると、次の人物の事情の入口も消える。** 南で試験を済ませてから北へ行くと、quarry.intro.memory は非表示になり、quarry.intro.familiar が「私の申し出を決めるのは、そのあとにする」と始まる。この経路ではネネの申し出自体をまだ聞いていない。その後、息子の記憶の撤回が出て初めて事情を補完した。終了後照合で、intro.memory は not(knows(truth.exception))、familiar は既知条件と確認（game.json:680 / :689）。改善案は、新人物の申し出や息子との関係を秘密とは別の入口として残し、既知なら誤信の解説だけを短縮する。知識の取得と、人物の事情を聞いた経験を別に扱うとよい。

終了手段についての補足: `--steps` のJSON viewには finish の案内がなく、残り4時間で空の選択肢を見た時に手順確認が必要だった。ただし CLI help には finish（src/cli.ts:149）、interactive には end（:123）、ブラウザUIには「灰潮を待って探索を終える」ボタン（src/player/ui.ts:44）がある。ゲーム全体のエンディング欠落ではない。ブラウザは実際には操作していない。

## 制作手法が支えたものと、まだ証明できないこと

終了後に読んだ implementation-notes.md:16–20 の作者の真実・信念・資料・観測の分離は、今回の「観察だけで効力は断言しない」から「記録と試験で判断する」への更新を支えていた。開示条件と既知用の台詞は、南で得た理解を北へ運ぶ挙動として実際に見えた。ただし既知用台詞は人物の事情まで省き、知識管理と会話導入の区別には改善余地がある。

共通の72時間、移動12時間、資源6単位という契約（同:28–38）は、二つの局所エピソードを一回の旅の取捨選択にした。南を全部済ませると北の24時間仕事をできない条件は意図通り（同:53）だった。しかし到達可能性と条件の整合は、初見プレイヤーが制約を予見して選べることの証明にはならない。

草稿から行動・条件・結果へ変換した方法は、道の破壊をその場と結末の両方へ残すことを支えていた。名前空間、採用履歴、全状態の到達性、Jev評価、別経路の魅力についてはこの一経路から独立に検証できない。notes に記載された検証結果を自分で再実行したわけではない。画像・画面レイアウト・操作性・人間の感情反応も対象外。

## 人間に確かめる最小のプレイテスト

世界設定を知らない3人に、ブラウザ版で一経路を自由に進めてもらう。各15分を上限にし、作者用資料と「正しい発見」の説明は渡さない。南の修理直前、北の調査後、結末で一度ずつ、次を短く聞く。

- 今の選択で何が残り、誰にどの仕事が増えると思うか。
- 粉が何をし、記憶を差し出すと何を失うと思うか。
- 北で修理できない場合、その理由は何だと思うか。南をやり直すなら変えるか。
- ネネは何を申し出ていたと思うか。気になった人物を一人挙げ、理由を述べてもらう。

狙いは理解・予測・人物への関心を分けて観測すること。本文に書かれた結論を覚えているだけか、次の選択へ使えているかを確認する。3人では好みの一般化や効果の統計的証明はしない。
