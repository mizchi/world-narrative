# 灰潮の入り江 — 並列制作の凍結ブリーフ

正史版: `ash-v0.1`。以下は今回の制作実験のためのオリジナル設定。出力は採用前の提案であり、正史を書き換えない。

## 体験の約束

美しい景観の維持に誰の負担が使われているかを、設備・生態・生活から発見する。プレイヤーは探索し、仕組みを試し、負担の置き方を選ぶ。ジャンルはダークファンタジー。

## 凍結した世界の事実

| ID | 作者の真実 |
| --- | --- |
| rule.tide | 月に二度、海から「灰潮」が来る。触れた金属と石は表面から崩れる。人体には直接の作用を持たない。 |
| rule.bell | 焼成した「記憶石」を鐘で砕き、その粉を水門に流すと、その水門の内側は次の一潮だけ灰潮の侵食を免れる。 |

| actor.ira | 港の鐘守イラは配分を決める責任がある。全員の暮らしを守りたいが、記憶石を使わずに防潮する手段を知らない。 |
| ecology.bird | 灰羽鳥は灰潮の直前に内陸へ逃げる。帰巣経路は古い運河と一致する。鳥に超常能力はない。 |
| truth.exception | 記憶石の粉の効力は人の犠牲の大小では増えない。水門へ届く粉の量と流路で守れる範囲が決まる。これは組合の一般作業員には知られていない。 |

## 制作時に守ること

- 蘇生、記憶の復元、記憶石の読み取り、灰潮そのものの停止を追加しない。
- 記憶の提供は自発的。強制・恐喝・制度上の圧力は対立として扱えるが、魔法で本人の意思を上書きしない。
- 記憶の提供を強制したから効力が増す、という規則は作らない。
- 現時点で最良の配分を一意に決めない。各エピソードの結果を作者の道徳的な正解へ統一しない。
- `truth.exception` は初期の会話やアイテム説明で明かさず、流路の観察・作業記録・小規模な実験などを経て発見させる。
- `history.break` の原因は確定しない。噂や仮説を追加する場合、その出所を明示する。

## 独立した二つの担当

### tide: 南の水門

一潮分の資源をどう使うかを迫られる局所エピソード。`tide.*` の人物・設備・資料を追加してよい。港や北の採石場の状態を変更せず、他エピソードを必須の前提にしない。

### quarry: 北の採石場

記憶石の生産と生活の維持をめぐる局所エピソード。`quarry.*` の人物・設備・資料を追加してよい。港や南の水門の状態を変更せず、他エピソードを必須の前提にしない。

両担当とも共有資源の確定した配分、灰潮の原因、主要人物イラの結末は決めない。それが必要なら「正史への変更要求」に返す。各地の供給や防潮の判断は、その地域の局所的な結果として書く。

## 出力の契約

担当の Markdown ファイル一つに、次の順で書く。約 1,200–2,000 字を目安とする。

1. 正史版、担当、エピソード名、参照した正史 ID。
2. 新しく提案する要素と ID。作者の真実・信念・資料・未確定を区別する。
3. 開始状況と人物の欲求。プレイヤーが関わる理由。
4. 三つ以上の具体的な発見。取得条件、媒体、知識がどう変わるか。
5. 二つ以上の介入。前提・費用・局所的な結果と、選ばなかった場合の結果。
6. ゲームで読める短い断片を二つ。作者用の裏設定を全文露出しない。
7. 変更要求、未解決点、到達性と整合性のセルフチェック。

検証は、正史への衝突、知識の飛躍、選択の実質的な差、他担当への暗黙の依存、断片の早期開示を確認する。同じモデルの二ライターで作るため、二人が同意したことを品質の証明にはしない。
