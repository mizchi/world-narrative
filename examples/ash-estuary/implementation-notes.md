# 灰潮の入り江 — MVP の採用調整

2026-10-03。`docs/mvp-plan.md` と `src/world/types.ts` の v1 契約に合わせ、凍結ブリーフと二つの Markdown 草稿をゲーム用の操作へ変換した。調整は以下の四ファイルに限定した。

- `world.json`: 正史版 `ash-v0.1`。場所、共通変数、述語、規則、作者の真実と未確定事項。初期の `episodes` は空。
- `tide.proposal.json`: 南の水門「白い道を剝ぐ」。局所の人物・設備・資料・主張と、三調査、道の修理、三配分、見送りを追加する。
- `quarry.proposal.json`: 北の採石場「白い階段の欠け」。局所の人物・設備・資料・主張と、三調査、相互排他の二作業、見送りを追加する。
- 本ファイル: 草稿からの採用調整、遊べる経路、確認結果と保留事項。

両提案は `ash-v0.1` を読んで独立に起案している。逐次採用する際は、先に採用した提案による差分と参照集合を照合したうえで、後の提案の `basedOnRevision` を現在の正史版に合わせる。古い版をそのまま二度採用できることは前提にしていない。

## 型と作者の情報

全 Claim の scope は `main` / `atemporal` / `always`。新しい ID は各提案の `tide.` または `quarry.` 内に置いた。`writeSet` は追加する Entity / Claim / Assertion / Episode と、Episode 内の全 Action / Fragment を列挙する。`readSet` は既存の述語、主語、場所、秘密命題、共通変数、資料・作者参照を列挙する。提案は他担当の Entity や Action を追加・変更しない。

設備の仕組みを authorTruth、スイとネネの「重い記憶ほど効く」という誤信を belief、帳面の記述を record として区別した。追加 Assertion は採用前の `proposed` とし、作者の採用操作で `accepted` へ変える。信念と資料が作者の真実へ自動的に昇格することはない。ゲームで得る局所の観測も `observed` のままにし、`known` は開示条件を満たした秘密にのみ使う。

`truth.exception` は初期正史で accepted の authorTruth として保持する。開示規則は `tide.tested == true OR quarry.trialRead == true`。南の `tide.test` は点検と検量帳の後、北の `quarry.read-trial` は夜勤帳と流路の後に選べる。どちらも必要な調査フラグを先に `set` し、それから秘密を `learn(mode: known)` する。

初期の台詞、場所の説明、行動の説明は秘密を断言しない。秘密の本文を含む断片には `knows(truth.exception)` を付け、各地の発見断片は現地の調査フラグも要求する。二つ目の地域では既知の理解を持って観測を続ける台詞を用意し、静的にも検査できるよう `all(knows(secret), reveal条件)` を使う。試験は、その地域で判断に使える根拠として説明し、数回の記録で全世界の規則を証明したとは語らない。砂・色水は流路の目印であり、防護魔法の代用品ではない。

石に移った記憶の復元、読み取り、意思の魔法による上書き、灰潮の停止、灰羽鳥の超常能力は forbidTruth 規則で禁止する。四十年前の堤防崩壊原因は初期 World の openQuestion に残した。

## 時刻の調整

草稿の南「灰潮前日の夕方」と北「灰潮まで二日」は、同じ初期時刻では両立しない。ゲーム全体の開始から七十二時間で灰潮が来る契約に統一した。各地の到着時刻を固定せず、プレイヤーの経過時間で残りを表示する。港の文は「探索を始めた時、灰潮まで七十二時間だった」として、再訪時にも残り時間を誤って断言しない。

港と各地域は往復とも十二時間。南北の直通路はなく、移動には港を経由する。各調査は一時間、南の道修理は十二時間、配分と見送りは一時間、北の作業は各二十四時間。北の草稿の発見3「供述と流量」と発見4「石板の現物」は、一時間の照合行動にまとめて三調査にした。北の四人の作業員を一日だけ使う制約は、`quarry.choice` による排他として扱う。

## 供給と選択の調整

草稿では南の割当と到着が未確定で、北の窯修理は今便の生産延期を起こす。実装では南に回せる今回の配分枠を `world.powder = 6` に定め、北岸の既存割当とは区別した。値は手元の袋の位置ではなく、今回使える共有の配分枠を表す。北の今便を止める窯修理は未配分枠を二単位減らす。

南の片側保護は四単位。槽を守れば干し場の枠が失われ、枠を守れば槽が失われる。道修理だけでは粉や保護を増やさない。修理と三調査を済ませた後に六単位を分けると、両側を一潮だけ守れる。その費用として白い道と荷車の通行を失う。三配分と見送りは `tide.decision == pending` を要求し、一度決めた後は選び直せない。道修理も配分前に行う。

北の窯修理は夜勤を減らすが、石段の修繕収入と溝の損失は残る。未配分枠が二以上ある場合にだけ選べる。南で四単位使った後でも窯修理できるが、六単位を使い切った後は選べない。すでに行った保護を供給延期で取り消すことも、資源を負へ落とすこともしない。

北の溝修理は、北岸へすでに割り当てられた粉の途中損失を減らす。`world.powder` には加算しない。溝を直したら北岸の全域が必ず守れる、という結果も追加しない。二日閉める洗い場の代わりに上の井戸から水を運ぶ負担が残る。窯と溝は `quarry.choice == pending` の条件で相互排他にした。

実装では記憶提供を受理・強制する行動を追加していない。ネネが資料を見て申し出を取り下げる断片は本人の判断として扱い、修理の条件にはしない。提供を巡る圧力は夜勤帳の記録で読める。

各地域を未訪問のまま終えることも、現地で明示的に見送ることもできる。終了断片は南の槽・枠・両側・放置、北の窯・溝・放置をそれぞれ core 変数で判別する。南で修理だけした場合には道を失った費用も別の断片で残す。保護、労働、運搬、水運びの負担を一つの道徳的な正解にまとめない。

## 確認した経路

| 経路 | 行動後の時刻 | 未配分枠 | 結果 |
| --- | ---: | ---: | --- |
| 港→南、点検・帳面・試験、道修理、両側配分 | 28時間 | 0 | 槽と枠を守り、白い道と荷車の通行を失う。北は未選択のまま終えられる。 |
| 港→南、三調査、槽へ四単位→港→北、三調査、窯修理 | 67時間 | 0 | 槽を守り枠を失う。北の夜勤を減らし、石段と溝の課題を残す。両episodeのcompletionが成立する。 |
| 港→北、三調査、溝修理→港→南、三調査、枠へ四単位 | 67時間 | 2 | 枠を守り槽を失う。北の粉の損失を減らし、洗い場の停止と窯の夜勤を残す。両episodeのcompletionが成立する。 |
| 初期状態で終了 | 72時間に進めて終了 | 6 | 両地域の放置結果を読み、未配分枠の残存も示す。 |

南の道修理まで行い、北で二十四時間の仕事も行う経路は締切に入らない。必要な調査だけに絞っても、南の修理と片側配分、北の作業、三回の移動で最低七十六時間となる。全ての改修を同じ旅で済ませられないことを、共通の時間制約として採用した。

## 検証と保留

探索・Red として三 JSON の存在と最小契約を検査し、未作成ファイルによる失敗を確認した。作成後は `parseWorld` / `parseProposal` の strict schema を通した。初期 World の `validateWorld` は `valid`、追加 ID の名前空間と完全な writeSet も確認した。

player runtime を使った経路の assertion は全て通った。未調査時に秘密の断片が表示されないこと、調査後に known を得ること、選択後の別配分・別作業が選べないこと、六単位を使った後に窯修理できないこと、各終了で南北それぞれ一つの選択結果を表示することを確認した。全体の `checkReachability` は `complete`、1,153状態、840終端、未到達 Action / Episode と findings はゼロだった。

初回の統合 `validateWorld` は、既知の秘密を扱う二つの `intro.familiar` だけを `early-disclosure` と診断した。runtime で知識を得るには開示フラグが必要だが、静的検証が任意の知識状態を独立に列挙していたためである。統合担当の指示で `all(knows(secret), reveal条件)` に変更し、追加 Assertion の status も `proposed` に揃えた。修正後は両提案の `previewProposal` が `valid`。メモリ内で南を採用し、北の正史版を合わせて採用した二件の履歴を検査し、全 Assertion が `accepted`、統合 World が `valid` となることを確認した。到達性と代表経路も再検査して同じ結果だった。ブラウザ E2E と Jev 補助評価は統合担当側で確認する。

次月の買い取り条件、石段修繕の仕事が戻るか、堤防の崩壊原因、イラの全域配分と結末は未確定のまま。買い取り条件は草稿と提案 notes に残し、Proposal に未定義の addOpenQuestion 操作を追加しなかった。
